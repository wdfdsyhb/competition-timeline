# 数据源实测报告

实测时间：2026-10-22 · 方法：Python urllib 直连（无代理、无浏览器渲染），逐源验证可达性、URL 模式、时间结构化程度

---

## 一、结论

**存在一个可直接用的 S 级源，能一次性拿到 182 条榜单竞赛的结构化时间。**

不是靠爬文章正文抽日期——那个源**列表页自带结构化时间字段**，格式固定到可以正则直取：

```
【榜单赛事】2026新锐设计竞赛·华灿奖
  摘要: 2026新锐设计竞赛·华灿奖||创意赛道作品征集截止时间：2026年11月27日17:00||
        校赛截止时间：2026年12月29日17:00||赛区赛截止时间：2027年1月29日17:00||
        定向主题作品征集截止时间：2027年3月5日17:00
```

`赛事名||阶段名：时间||阶段名：时间||…` 这个分隔符结构是稳定的。这意味着 P0 阶段的数据录入可以**半自动**，不用人工从通知正文里抄日期。

官方源（高教学会、教育部、各竞赛官网）全部可达，但都只提供**正文日期**，需要逐篇抽。所以架构应该是双层的：**聚合源做发现与时间种子，官方源做核验与权威背书**。

## 三、S 级源详解

### 我爱竞赛网 52jingsai.com

**索引地址**
```
https://www.52jingsai.com/bisai/xkjn/bangdan/
```

**这页是完整可查询的** —— 它是 `index.php` 驱动的筛选器，参数全部实测有效：

| 参数 | 取值 | 含义 |
|---|---|---|
| `jsstatus` | 0 / 1 / 2 / 6 | 不限 / 即将报名 / **正在报名** / 报名结束 |
| `jsrank` | 0 / 1 / 2 | 不限 / 全国 / 各省 |
| `areaid` | 1–30 | 省份（安徽 1、江苏 2、北京 4、重庆 5、福建 6、甘肃 7、广东 8、广西 9、海南 10、河北 11、黑龙江 12、河南 13、湖北 14、湖南 15、江西 16、吉林 17、辽宁 18、内蒙古 19、宁夏 20、青海 21、山东 22、上海 23、山西 24、陕西 25、四川 26、天津 27、新疆 28、西藏 29、云南 30） |
| `jssort` | 3 = 按时间 | 排序 |
| `page` | 1–12 | 分页，每页 15 条 |

实际请求形如：
```
https://www.52jingsai.com/bisai/xkjn/bangdan/index.php?jsstatus=2&jssort=0
https://www.52jingsai.com/bisai/xkjn/bangdan/?page=2
```

**实测规模**：12 页翻完，去重 **182 条**榜单竞赛文章。标题里带「榜单赛事」92 条、「榜单竞赛」38 条。

**列表页每条记录可提取的字段**
- `article-<id>-1.html` → 文章 ID（可作稳定主键）
- 标题 → 赛事名（`【榜单赛事】`/`【榜单竞赛】` 前缀需剥离）
- 摘要 → **结构化时间**，`||` 分隔，含「报名截止时间」「作品征集截止时间」「校赛截止时间」「赛区赛截止时间」
- 摘要尾部含**主办单位**
- 列表页含**发布时间**（`2026-10-13 09:47` 格式）

**文章详情页**：`https://www.52jingsai.com/article-<id>-1.html` 可访问；正文里含完整通知文字，且**给出官网报名地址**（例：华灿奖文章内 `官网报名地址： https://www.cahe.edu.cn/site/term/906.html`）。

**风险与对策**
- 站点自身声明「信息搜集整理自互联网，版权及活动解释权归主办单位所有，我爱竞赛网仅作媒体支持」——所以**它只能当发现层，不能当权威源**。数据模型里的 `source` 字段必须存官方 URL，not 52jingsai URL。
- 无 robots.txt 冲突验证（未测），抓取需限速（建议 1 req/s + 夜间跑）。
- 第三方站会改版，解析器要写成**失败即告警**而非静默返回空。

## 六、对方案的影响

原方案的三层架构不变，但数据层要加一层「抓取导入」：

```
原始抓取 (S级: 52jingsai 索引)
   ↓ 解析器：剥前缀 → 拆 || → 阶段名映射 → 日期规范化
   ↓ 生成 candidate YAML（confidence: tentative）
人工/官方核验 (A级: cahe / moe / 竞赛官网)
   ↓ 补 source{url,title,published_at}
   ↓ 升级 confidence: confirmed
data/competitions/<slug>.yml + data/schedules/<slug>/<year>.yml
   ↓ build.py 校验（source 必填、日期合理性）
ICS / JSON / 静态站
```

**`confidence` 三档在这个流程里有了明确来源**：
- `confirmed` — 官方通知正文核验过，`source` 指向官方 URL
- `tentative` — 58jingsai 摘要给出但未经官方核验（**这是自动导入的默认档**）
- `estimated` — 基于往届规律推算（例：数模每年 9 月第二个周四）

**新增决定**：`source.type` 要区分 `official` / `aggregator`。UI 上聚合源来的数据必须带「待核验」标记，且链接指向官方站而不是 52jingsai。

## 七、解析可行性实测（10 条样本）

已跑通一次端到端解析：**10 条里 6 条自动抽出阶段时间**。

抽成功的样例：
```
[24115] 第十一届华为ICT大赛中国赛
    · 实践赛报名截止   2026年10月31日
    主办 华为技术有限公司
[24114] 2027第十一届米兰设计周-中国高校设计学科师生优秀作品展
    · 报名             2026年10月至2027年4月
[24109] 2026年第十四届全国大学生数字媒体科技作品及创意竞赛
    · 报名及作品提交   2026年10月23日23:59:59
[23944] 大学生语言文字能力大赛规范字专项赛
    · 报名             2026年11月20日中午12点
```

**未抽到时间的 4 条不是解析失败** —— 它们是证书考试类条目（Office 办公技能证书、普通话水平测试），时间写在标题里（`【10月24日全国统考】`），本身没有多阶段赛程。这类占榜单页约 1/4，需要在导入时归类或剔除。

**已暴露的两个 bug（P0 要修）**
1. 标题截断：`【10月24日全国统考，Office办公技能证书】` 后面断了 —— 锚点文本里有嵌套标签，`[^<]{4,200}` 正则不够
2. 主办单位串味：`华夏文化促进会文化产业工作委员会、大学生汉语大赛组委会||报名时间：即日` —— 边界词选错，需在 `||` 和数字/时间处切断

**非标准日期格式**（要专门处理）
- `即日起至2026年12月19日下午5点`
- `2026年11月20日中午12点`
- `2026年10月至2027年4月`（区间）
- `2026年10月23日23:59:59`（带秒）

## 八、P0 起手式

1. 写 `tools/fetch_52jingsai.py`：翻 12 页 → 182 条 → 解析成 candidate JSON
2. 修上面两个 bug，再抽 20 条核对，目标自动解析率 ≥70%（剔除证书考试类后可到 85%+）
3. 定 `data/` schema，把核验通过的写成正式 YAML
4. 再扩量

预估：P0 半天可完成。真正的成本在**核验**（每条要打开官方通知确认），这块没法自动化，182 条全核验约 2–3 天人工量。
